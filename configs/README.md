# configs/ -- what is actually read, and what is not

Not all three subdirectories here mean the same thing. Read this before assuming any of
them controls a real run.

| Directory | Read by code? | What actually controls the run |
|---|---|---|
| `configs/san/` | **Yes** -- `backends/san_backend.py:build_san_net_params` / `build_san_train_params` load `san_<pe>_<dataset>.json` directly. | These files. Generated by `scripts/generate_san_configs.py` from `san_backend.py`'s own `PE_SPEC` / `BASE_NET_PARAMS` / `TRAIN_PARAMS` -- re-run that script after changing any of the three, don't hand-edit the JSON. |
| `configs/graphgps/` | **No.** | `backends/graphgps_backend.py:build_graphgym_cfg` starts from GraphGPS's **own** tuned reference YAML inside the cloned fork (`../GraphGPS/configs/GPS/*-GPS.yaml`) and overrides the PE block in Python. These 15 files are a decorative leftover from before that integration landed -- they were never wired up, and running a cell does not consult them. Kept for now as a record of the pre-integration design rather than deleted outright; do not edit them expecting it to change a run. |
| `configs/graphormer/` | **No.** | The Graphormer backend is still a stub (`run_experiment.graphormer_train` raises `NotImplementedError`), so nothing reads these yet. Once a real `graphormer_backend.py` exists, decide then whether it follows GraphGPS's pattern (defer to Graphormer's own reference configs, e.g. fairseq-cli examples) or SAN's (this repo's JSON files are the live source) -- don't assume either without checking what Graphormer itself ships. |

## Why SAN's are wired and GraphGPS's are not

Not an oversight in one direction or the other -- it follows from what upstream actually
ships. GraphGPS *is* the LRGB benchmark's own reference codebase, so it has tuned,
peer-reviewed configs for our exact three datasets; deferring to them is strictly better
than this project's own guess. SAN predates LRGB and ships no LRGB configs at all (see
`backends/san_backend.py`'s module docstring), so there is nothing upstream to defer to --
this repo's JSON files are the only config that exists for the SAN arm, and there was no
reason to leave them unread the way GraphGPS's legacy YAMLs are.
